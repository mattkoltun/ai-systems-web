1 · core vocabulary

The system is more than the model.

A useful mental model is to separate execution environment concepts from AI application concepts. Workspaces, sandboxes, containers and shells define where things run. Harnesses, tools, MCP, skills, models and agents define what behavior is possible inside that environment.

Execution scope

Workspace

A durable project context: files, repositories, settings, environment, permissions and sometimes multiple sandboxes. Think of it as the top-level place where work lives.

Isolated execution

Sandbox

A safe environment created for a task or session. It limits damage, scopes resources and lets an agent inspect code, run commands and edit files with guardrails.

Packaging boundary

Container

A packaged runtime with filesystem, process space and dependencies. Sandboxes are often implemented using containers or container-like isolation, though they are not conceptually identical.

Human / agent entrypoint

Shell

A command interpreter inside the environment. Bash, zsh, fish or PowerShell expose processes and files. The shell is one tool inside the container or sandbox — not the sandbox itself.

Reasoning engine

Model

The inference system that predicts text or structured tool calls. It does not own files or processes by itself; it acts through the harness and tools around it.

Control plane

Harness

Application logic that composes prompts, manages memory, picks tools, validates calls, handles retries, approvals and state transitions.

Capability surface

Tool / MCP server

Concrete operations such as read_file, search_logs, run_shell_command, fetch_url or list_tickets. MCP standardizes how external capabilities are exposed.

Coordinated system

Agent

A model plus harness plus capabilities operating over multiple steps toward a goal. The “agent” is the whole loop, not just the model.

2 · containment model

What contains what?

These terms are often mixed together. The key is to think in nested boundaries. Not every product uses the exact same layers, but the pattern below is common.

Outer organizational scope

Workspace

May contain repositories, configuration, task history, secrets references, and one or more execution environments. A workspace is usually persistent across sessions.

Per-task or per-session execution

Sandbox

Created to safely perform work. It may mount part of the workspace, expose only some tools, and enforce limits on CPU, memory, network and filesystem access.

OS-level isolation / packaging

Container

Often used to implement the sandbox. Provides processes, filesystem and dependencies. One sandbox may correspond to one container, though products may use lighter or heavier isolation models.

Interactive process inside the environment

Shell

The shell runs inside the container or sandbox. It is an interface to start commands, inspect files and chain programs. Shell commands are one type of tool an agent may call.

Application logic inside or alongside the environment

Harness + tools + model

The harness may live outside the sandbox while dispatching operations into it, or partly inside it. The model decides; the harness orchestrates; the tools act.

A good shorthand: workspace is where the work belongs, sandbox is where the work executes, container is how isolation is packaged, and shell is one interface inside that environment.

4 · detailed taxonomy

Execution concepts vs AI concepts

Execution environment terms

  • Workspace: durable project scope; often contains code, tasks, settings and history.
  • Sandbox: temporary or semi-persistent execution environment for safe work.
  • Container: process/filesystem isolation package that may back the sandbox.
  • Shell: interactive command runner inside the environment.
  • Process: a running program such as node, python, git, ripgrep or pytest.
  • Filesystem: the mounted files visible to the sandbox and shell.

AI application terms

  • Model: predicts tokens and tool calls.
  • Tool: callable capability with schema and runtime behavior.
  • MCP: protocol for exposing tools/resources/prompts.
  • Skill: reusable guidance, recipes, prompts, examples or scripts.
  • Harness: orchestrator that turns model output into safe action.
  • Agent: the end-to-end loop coordinating reasoning and action.

7 · implementation notes

      
What to build if you were implementing this yourself

      

        
Workspace manager
Knows which repos, files, secrets and task history belong to a user or project.

        
Sandbox manager
Creates isolated environments, mounts files, enforces limits and destroys or snapshots them.

        
Tool runtime
Executes shell, file, search, browser and API tools with validation and timeout handling.

        
Harness
Shapes prompts, selects context, interprets tool calls, requests approval, stores checkpoints and formats answers.

        
Model gateway
Calls one or more models and normalizes tool-call output and response formats.

        
Observability
Traces every step: prompt, tool call, shell command, file diff, errors, tokens and final output.
